## Architecture

**Framework stack:** TanStack Start (SSR React framework) + TanStack Router (file-based routing) + TanStack Query (data fetching) + TanStack Store (client state). Deployed to Cloudflare Workers via `@cloudflare/vite-plugin`.

**Path alias:** `#/*` maps to `src/*` (configured in `package.json` `imports` and `tsconfig.json`).

### Data flow

The feed page (`src/routes/index.tsx`) uses a two-layer query model:
1. **Layer 1** — `feedStoryIdsQueryOptions(feed)` fetches the full list of story IDs for the active feed (top/new/best). Stale after 60s.
2. **Layer 2** — `storyItemQueryOptions(storyId)` fetches each story individually and progressively. Stale after 5 min.

The route loader (`loader` in `index.tsx`) SSR-prefetches the ID list and warms the cache for the first `PAGE_SIZE` items. On the client, switching tabs or loading more items fetches incrementally without resetting previously loaded tabs.

All HN API calls go through `src/lib/hacker-news/queries.ts` (direct calls to `hacker-news.firebaseio.com`). Normalization (`normalizeStoryItem`, `normalizeStoryIds`) strips dead/deleted items and coerces types before anything touches React.

### Favorites

`src/lib/favorites-store.ts` is a `@tanstack/store` instance that persists to `localStorage` under `hackerfeed:favorites`. It stores the full `HackerNewsStoryRecord` (not just IDs) so favorites render without re-fetching. Actions: `toggleFavorite`, `isFavorited`, `getFavorites`, `clearAllFavorites`. Subscribe with `useStore(favoritesStore, selector)` in components.

### Auth

WorkOS AuthKit owns the session entirely in the browser (`src/integrations/workos/provider.tsx`, `devMode` keeps the refresh token in localStorage). There are no HackerFeed session cookies. `AuthGate` in `__root.tsx` sends signed-out users to WorkOS; only `/auth/callback` and `/auth/signed-out` are public. API calls (tRPC, `src/lib/ai/client.ts`) send `Authorization: Bearer <access token>` via `getAuthHeaders()` in `src/lib/auth/authkit.ts`; the server verifies it against WorkOS's JWKS with `getRequestUser()` in `src/server/auth/workos-access-token.ts`.

### Logging and debugging

Use `logger` from `#/lib/logger` everywhere (browser and Worker), never `console.*`. Each call goes to Sentry Logs (structured, linked to the trace) and the console. Pass the caught value as `error`: `logger.error(msg, { error })` also creates a Sentry issue. Use `warn` where you log and rethrow, so only the code that handles the error reports it. Error screens show the trace ID (`useErrorReport` + `TraceIdNote`). To debug a report, search `trace:<id>` in Sentry for the issue, logs and browser→Worker spans.

### Routing

Routes live in `src/routes/`. `routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin — do not edit it manually. Add new routes by creating files in `src/routes/`; the plugin regenerates the tree on the next dev-server restart or build.

The root layout (`src/routes/__root.tsx`) wraps every page in `TanStackQueryProvider`, `AppShell`, `SiteHeader`, and `SiteFooter`. It injects a blocking inline script to resolve the dark/light/auto theme before first paint to avoid flash-of-wrong-theme.

### UI components (atomic design)

Every component lives in one of four layers under `src/components/`. Read a file top-down and it should say *what* is on screen; *how it looks* lives only in the bottom two layers.

| Layer | What goes here | Styling (`className`/`style`) | Data / hooks |
|---|---|---|---|
| `atoms/` | One styled element: `Button`, `ButtonLink`, `TextLink`, `Text`, `Heading`, `Kicker`, `Stack`, `Row`, `Card`, `Panel`, `PageContainer`, `Skeleton`, `Icon`, `Avatar`, `TextInput`… | Yes, the only place Tailwind classes are written | No |
| `molecules/` | A few atoms composed into a reusable piece: `TabList`, `EmptyState`, `StatusPanel`, `BackLink`, `MetaLine`, `LoadingScreen`… | Yes, layout glue only | No, props in, callbacks out |
| `organisms/<feature>/` | A feature section with behavior: `StoryCard`, `SiteHeader`, `Comment`, `PapersFeed`… | **No** | Yes |
| `pages/` | The full body of one screen, rendered by a route: `FeedPage`, `StoryPage`, `PapersPage`… | **No** | Yes |

Routes in `src/routes/` stay thin: route config, loader, search params, then render a page. They follow the same rule as pages.

Rules, enforced by Biome (`bun run check`):
- `lint/no-styling-outside-atoms.grit` rejects `className` and `style` in `organisms/`, `pages/` and `routes/`. If no component fits, add an atom/molecule (or a variant) instead of styling inline.
- `noRestrictedImports` stops atoms and molecules from importing `#/hooks`, `#/lib`, `#/server` or higher layers, so they stay presentational.
- `noRestrictedElements` rejects raw `<button>` outside atoms/molecules; `lint/no-button-look-classes.grit` rejects class strings that recreate the button look.
- Exempt: tests, and the stylesheet-free error UI in `client-entry.tsx`.

Prefer props that describe intent (`tone="soft"`, `size="page"`, `variant="accent"`) over props that leak CSS. Selected state for `Tab` and secondary `Button` chips comes from the caller's `aria-selected`/`aria-pressed`. Tests that mock `@tanstack/react-router` must provide `createLink` (see `src/test/createLinkMock.tsx`), because the link atoms are built with it.

### Testing

Vitest is configured with two projects (`vitest.config.ts`):
- **`node`** — pure utility and store tests (`src/**/*.test.{ts,tsx}`, excluding `src/components/**` and `*.browser.test.*`)
- **`browser`** — component and browser-API tests using `happy-dom` (`src/components/**/*.test.*` and `src/**/*.browser.test.*`)

Use the `.browser.test.ts` suffix for anything that touches `window`, `localStorage`, or DOM APIs.
